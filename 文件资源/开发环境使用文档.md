# 团队开发环境使用文档（Docker + GitHub Actions）

## 1. 目标

- 统一跨平台（Windows/macOS）本地开发环境：前端 + 后端 + 本地 RAG 索引（FAISS）
- 通过一键脚本快速启动、停止与重建，避免环境差异
- 使用 GitHub Actions 在 feature 分支与 PR 阶段自动化构建与检查

## 2. 前置要求

- 安装 Docker Desktop（最新稳定版本，启用 Compose v2）
- 具备云数据库与云 OSS 的访问凭证（后端运行时通过环境变量读取）
- 克隆仓库后，准备环境变量文件：
  - 复制 `.env.sample` → `.env.dev`，填入真实值：
    - `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PASS`
    - `OSS_ENDPOINT`
    - `FAISS_INDEX_PATH`（默认 `/faiss`，脚本会挂载到 `data/faiss`）

## 3. 一键启动（macOS/Linux）

- 启动：
  - `bash docker/dev-up.sh`（默认使用 `.env.dev`；不存在时回退 `.env.sample`）
  - 指定环境文件：`bash docker/dev-up.sh /绝对路径/.env.dev`
- 访问：
  - 前端：`http://localhost:5173`
  - 后端：`http://localhost:8080`
- 停止：
  - `bash docker/dev-down.sh`
- 重新构建（包版本更新后）：
  - 普通重建：`bash docker/dev-build.sh`
  - 强制不使用缓存：`NO_CACHE=1 bash docker/dev-build.sh`

## 4. 一键启动（Windows / PowerShell）

- 启动：
  - `powershell -ExecutionPolicy Bypass -File docker\dev-up.ps1`
  - 指定环境文件：`powershell -ExecutionPolicy Bypass -File docker\dev-up.ps1 -EnvFile C:\路径\.env.dev`
- 访问：
  - 前端：`http://localhost:5173`
  - 后端：`http://localhost:8080`
- 停止：
  - `docker compose -f docker/compose.dev.yml --env-file .env.dev down`
- 重新构建（包版本更新后）：
  - 普通重建：`powershell -ExecutionPolicy Bypass -File docker\dev-build.ps1`
  - 强制不使用缓存：`powershell -ExecutionPolicy Bypass -File docker\dev-build.ps1 -NoCache`

## 5. 镜像加速（可选）

- 拉取基础镜像失败或很慢时，配置镜像加速：
  - macOS：`bash docker/dev-up.sh --setup-mirrors`，然后重启 Docker Desktop（Settings → Docker Engine → Apply & Restart）
  - Windows：`powershell -ExecutionPolicy Bypass -File docker\dev-up.ps1 -SetupMirrors`，然后重启 Docker Desktop

## 6. 目录与服务说明

- 使用云数据库与云 OSS：后端通过 `DB_*` 与 `OSS_ENDPOINT` 读取，不启动本地 MySQL/MinIO
- 本地 RAG 索引：
  - 路径：`仓库/data/faiss`
  - 容器挂载：`FAISS_INDEX_PATH=/faiss`
- 容器端口：
  - 前端：`5173`
  - 后端：`8080`
