# LLM缓存系统改进计划

## 1. 问题分析
当前LLM缓存系统存在以下问题：
- `generate_interpretation`方法没有使用缓存，直接调用LLM
- `chat`方法没有使用缓存，直接调用LLM
- `chat_with_references`方法没有使用缓存，直接调用LLM
- `_get_rag_context`方法没有使用缓存，每次都重新检索
- 缓存键生成逻辑可能不够完善

## 2. 改进方案

### 2.1 统一缓存检查流程
为所有LLM调用方法添加统一的缓存检查流程：
- `generate_interpretation`方法：添加缓存检查和存储
- `chat`方法：添加缓存检查和存储
- `chat_with_references`方法：添加缓存检查和存储
- `_get_rag_context`方法：添加缓存检查和存储

### 2.2 完善缓存键生成
确保缓存键包含所有影响生成结果的因素：
- 输入文本
- 相关参数（如dynasty）
- 上下文信息
- 模型信息

### 2.3 优化缓存存储和检索
- 确保缓存存储逻辑正确处理所有情况
- 优化缓存检索逻辑，提高性能
- 添加详细的日志记录，便于调试

## 3. 具体实现步骤

### 3.1 修改`generate_interpretation`方法
添加缓存检查和存储逻辑，确保在调用LLM前先检查缓存，生成结果后存储缓存

### 3.2 修改`chat`和`chat_with_references`方法
添加缓存检查和存储逻辑，确保对话内容也能被缓存

### 3.3 修改`_get_rag_context`方法
添加缓存检查和存储逻辑，减少重复检索

### 3.4 完善缓存键生成
确保缓存键包含所有影响生成结果的因素

### 3.5 优化缓存存储和检索
- 确保`set_llm_cache`方法能正确处理各种情况
- 确保`get_llm_cache`方法能正确返回缓存结果
- 添加详细的日志记录

## 4. 预期效果
- 减少LLM调用次数，降低成本
- 提高系统响应速度
- 确保相同输入产生相同结果，提高系统一致性
- 便于调试和监控缓存使用情况

## 5. 测试计划
- 测试缓存命中情况
- 测试缓存失效机制
- 测试缓存存储和检索的正确性
- 测试不同输入的缓存键生成
