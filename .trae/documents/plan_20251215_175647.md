# 碑说项目测试方案

## 1. 测试目标

- 验证项目各个模块的功能正确性
- 验证模块间的集成正确性
- 确保系统在各种情况下的稳定性
- 确保系统能够处理预期的负载
- 验证系统的安全性

## 2. 测试环境

- **前端**：Vue.js 3 + Vite
- **后端**：
  - Java Spring Boot 3
  - Python FastAPI
- **数据库**：PostgreSQL 15
- **缓存**：Redis 7
- **对象存储**：MinIO
- **测试工具**：
  - pytest（Python 后端单元测试）
  - 自定义测试脚本（集成测试）
  - Docker Compose（环境部署）

## 3. 测试类型

### 3.1 单元测试

- **Python 后端**：
  - RAG 搜索功能测试（test_rag_search.py）
  - 参考文献功能测试（test_references.py）
  - 流式响应功能测试（test_streaming.py）

### 3.2 集成测试

- **数据库访问测试**：test_database_access.py
- **LLM 缓存测试**：test_llm_cache.py
- **OCR 缓存测试**：test_ocr_cache.py, test_ocr_cache_after_restart.py
- **OCR 完整流程测试**：test_ocr_full.py

### 3.3 系统测试

- 端到端测试
- 性能测试
- 安全测试

## 4. 测试用例设计

### 4.1 前端测试用例

| 测试用例ID | 测试用例名称 | 测试步骤 | 预期结果 | 优先级 |

| FT-002 | 碑文识别测试 | 1. 点击碑文识别按钮<br>2. 上传图片<br>3. 等待识别结果 | 识别结果显示成功 | 高 |
| FT-003 | 人工校对测试 | 1. 进入校对页面<br>2. 修改识别结果<br>3. 保存修改 | 修改成功保存 | 中 |
| FT-004 | AI 阐释测试 | 1. 进入阐释页面<br>2. 等待阐释生成 | 阐释内容生成成功 | 高 |
| FT-005 | AI 对话测试 | 1. 进入对话页面<br>2. 输入问题<br>3. 等待回答 | 回答生成成功 | 高 |

### 4.2 后端测试用例

| 测试用例ID | 测试用例名称 | 测试步骤 | 预期结果 | 优先级 |

| BT-002 | 碑文创建测试 | 1. 发送创建碑文请求<br>2. 查询创建结果 | 碑文创建成功，查询结果正确 | 高 |
| BT-003 | LLM 缓存测试 | 1. 保存LLM结果<br>2. 查询LLM结果<br>3. 验证结果一致性 | 缓存保存成功，查询结果与保存结果一致 | 高 |

| BT-005 | 文件上传测试 | 1. 上传文件<br>2. 验证文件存在 | 文件上传成功，且可以访问 | 中 |

## 5. 测试执行计划

### 5.1 单元测试执行

```bash
cd python
pytest tests/
```

### 5.2 集成测试执行

```bash
cd python
python test_database_access.py
python test_llm_cache.py
python test_ocr_full.py
```

### 5.3 系统测试执行

1. **环境准备**：执行 `./start-dev.sh` 启动开发环境
2. **健康检查**：
   ```bash
   # 检查前端服务
   curl http://localhost:5173
   
   # 检查后端服务
   curl http://localhost:8080/actuator/health
   
   # 检查数据库连接
   docker exec -it beishuo-postgres psql -U beishuo -d beishuo -c "SELECT 1;"
   ```
3. **功能测试**：手动测试前端功能

## 6. 测试结果分析

- 单元测试：通过 pytest 输出查看测试结果
- 集成测试：通过脚本输出查看执行结果
- 系统测试：通过手动测试记录测试结果

## 7. 测试报告

测试完成后，生成测试报告，包括：

- 测试概述
- 测试环境
- 测试结果统计
- 测试用例执行情况
- 发现的问题
- 建议和改进措施

## 8. 回归测试

当系统有更新时，执行回归测试，确保原有功能不受影响：

1. 执行所有单元测试
2. 执行关键集成测试
3. 测试更新相关的功能

## 9. 测试维护

- 定期更新测试用例，确保覆盖新功能
- 维护测试环境，确保环境的稳定性
- 定期执行测试，确保系统的稳定性

## 10. 风险评估

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| 数据库连接失败 | 低 | 系统无法使用 | 定期检查数据库连接，添加重试机制 |
| LLM 调用失败 | 中 | AI 功能无法使用 | 添加降级机制，使用缓存结果 |
| 前端加载缓慢 | 低 | 用户体验差 | 优化前端代码，使用缓存 |
| 系统负载过高 | 低 | 系统响应缓慢 | 优化系统性能，添加负载均衡 |

## 11. 测试工具

- **pytest**：Python 单元测试
- **Docker Compose**：环境部署
- **curl**：API 测试
- **Postman**：API 测试
- **Chrome DevTools**：前端调试

## 12. 测试文档

- **测试计划**：本文档
- **测试用例**：测试用例管理系统
- **测试报告**：测试执行后生成
- **缺陷报告**：缺陷管理系统

## 13. 测试执行

- **测试负责人**：开发团队
- **测试时间**：开发完成后
- **测试频率**：
  - 单元测试：每次提交代码后
  - 集成测试：每周执行一次
  - 系统测试：每月执行一次

## 14. 测试结束标准

- 所有单元测试通过
- 所有集成测试通过
- 所有关键功能测试通过
- 发现的缺陷已修复或已记录在缺陷管理系统中
