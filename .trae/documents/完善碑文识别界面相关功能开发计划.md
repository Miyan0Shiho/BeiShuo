# 完善碑文识别界面相关功能开发计划

## 一、数据库结构分析

根据数据库导出文件，我分析了以下关键表结构：

1. **ocr_jobs**：存储OCR识别任务，包含状态、供应商等信息
2. **knowledge_articles**：存储知识文章，包含12条著名碑文记录（如乙瑛碑、九成宫醴泉铭等）
3. **inscriptions**：存储碑刻信息，有67条记录
4. **inscription_assets**：存储碑刻资产文件，有24条记录
5. **article_tag_map**：文章标签映射表（目前为空）
6. **tags**：标签表（目前为空）

## 二、功能实现方案

### 1. 相关碑文推荐功能

**实现思路**：
- 基于OCR识别结果文本，通过关键词匹配从knowledge_articles表中检索相关碑文
- 当识别失败或未执行时，从knowledge_articles表中随机推荐碑文
- 推荐结果包含碑文标题、简介及元数据

**技术实现**：
- 后端接口：`POST /api/v1/recommendation/inscriptions`
- 参数：
  - `ocr_text`：OCR识别结果文本（可选）
  - `limit`：推荐数量（默认5）
- 逻辑：
  1. 如果提供了ocr_text，使用关键词匹配算法推荐相关碑文
  2. 如果未提供ocr_text或匹配结果为空，随机推荐碑文
  3. 返回推荐的碑文列表，包含id、title、author、excerpt等字段

### 2. 最近识别记录功能

**实现思路**：
- 从ocr_jobs表中查询最近的OCR识别记录
- 关联查询inscription_assets和inscriptions表获取完整信息
- 实现分页加载，默认展示最近10条记录

**技术实现**：
- 后端接口：`GET /api/v1/recognition/history`
- 参数：
  - `page`：页码（默认0）
  - `size`：每页数量（默认10）
- 逻辑：
  1. 查询ocr_jobs表，按created_at倒序排序
  2. 关联查询inscription_assets和inscriptions表
  3. 返回识别记录列表，包含id、created_at、status、title等字段

## 三、数据库查询设计

### 1. 相关碑文推荐查询
```sql
-- 基于关键词匹配的推荐查询
SELECT id, title, author, content 
FROM knowledge_articles 
WHERE MATCH(title, content) AGAINST (%s IN NATURAL LANGUAGE MODE)
ORDER BY MATCH(title, content) AGAINST (%s IN NATURAL LANGUAGE MODE) DESC
LIMIT %s;

-- 随机推荐查询
SELECT id, title, author, content 
FROM knowledge_articles 
ORDER BY RAND() 
LIMIT %s;
```

### 2. 最近识别记录查询
```sql
SELECT oj.id, oj.status, oj.created_at, oj.asset_id, 
       ia.inscription_id, i.title 
FROM ocr_jobs oj
LEFT JOIN inscription_assets ia ON oj.asset_id = ia.id
LEFT JOIN inscriptions i ON ia.inscription_id = i.id
WHERE oj.status = 'success'
ORDER BY oj.created_at DESC
LIMIT %s OFFSET %s;
```
