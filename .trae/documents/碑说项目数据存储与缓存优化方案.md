# 碑说项目数据存储优化方案（无Redis依赖）

## 1. 方案概述

本方案旨在优化碑说项目的数据存储机制，在不影响现有业务且不依赖Redis的前提下，实现以下目标：

- 用户上传图片存储到阿里云OSS
- OCR识别前利用关系型数据库做缓存
- OCR识别结果结构化存储到数据库
- 业务数据完整存储到数据库
- LLM对话历史存储与数据库缓存

## 2. 数据库结构分析

从数据库导出日志中，我们可以看到项目已设计了完善的表结构，包括：

### 核心表结构
- `users` - 用户信息
- `inscriptions` - 碑文基本信息
- `inscription_assets` - 碑文资产（图片等）
- `inscription_text` - 碑文文本
- `inscription_text_versions` - 碑文文本版本
- `ocr_jobs` - OCR识别任务
- `ocr_images` - OCR识别图片
- `ocr_text_lines` - OCR识别文本行
- `ocr_words` - OCR识别的字
- `conversations` - 对话会话
- `messages` - 对话消息
- `llm_cache` - LLM响应缓存（已存在，可直接使用）

## 3. 实现方案

- 保持向后兼容，确保现有功能不受影响

#### 实现步骤
1. 完善OSS配置项（access_key_id、access_key_secret、endpoint等）
2. 添加OSS客户端工具类，封装上传、下载、删除等操作
3. 修改`uploadImage`方法：
   - 生成唯一文件名（保持现有逻辑）
   - 保存文件到本地（保持现有逻辑）
   - 同时上传文件到OSS

### 3.2 OCR识别前利用关系型数据库做缓存

#### 技术方案
- 使用现有`ocr_jobs`表和`ocr_images`表作为缓存
- 基于图片的MD5哈希值或唯一标识作为缓存key
- 实现缓存命中则直接返回，未命中则调用OCR服务

#### 实现步骤
1. 在`ocr_images`表中添加`image_hash`字段，用于存储图片的唯一标识
2. 在`ocr_jobs`表中添加`status`和`result`字段，用于跟踪OCR任务状态和结果
3. 修改`submitRecognitionTask`方法：
   - 生成图片哈希值
   - 查询`ocr_images`表，检查是否已有相同图片的识别结果
   - 若有，直接返回已有结果
   - 若无，创建新的OCR任务，调用OCR服务

#### 代码示例
```java
public String submitRecognitionTask(String imageId, String imageUrl) {
    // 生成图片哈希值
    String imageHash = generateImageHash(imageUrl);
    
    // 查询数据库，检查是否已有识别结果
    Map<String, Object> existingResult = databaseClient.getOCRResultByImageHash(imageHash);
    if (existingResult != null) {
        // 已有结果，直接使用
        logger.info("OCR结果从数据库缓存获取: imageId={}", imageId);
        // TODO: 使用已有结果创建inscription记录
        return existingResult.get("task_id").toString();
    }
    
    // 无已有结果，提交OCR任务
    String taskId = UUID.randomUUID().toString();
    
    // 创建OCR任务记录
    Map<String, Object> ocrJob = new HashMap<>();
    ocrJob.put("task_id", taskId);
    ocrJob.put("image_id", imageId);
    ocrJob.put("image_url", imageUrl);
    ocrJob.put("image_hash", imageHash);
    ocrJob.put("status", "pending");
    databaseClient.createOCRJob(ocrJob);
    
    // 调用OCR服务
    // TODO: 实现OCR服务调用
    
    logger.info("提交识别任务: imageId={}, taskId={}", imageId, taskId);
    return taskId;
}
```

### 3.5 LLM对话历史存储与数据库缓存

#### 技术方案
- 利用现有`conversations`和`messages`表存储对话历史
- 使用`llm_cache`表缓存LLM响应
- 实现对话上下文管理，提高对话连贯性

#### 实现步骤
1. 完善对话管理逻辑，确保所有对话都存储到`conversations`和`messages`表
2. 在LLM调用前，检查`llm_cache`表，命中则直接返回
3. LLM调用完成后，将结果写入`llm_cache`表
4. 实现对话上下文管理，基于`conversation_id`关联对话历史

#### 代码示例
```python
# 在ai/chat接口中添加数据库缓存逻辑
@router.post("/chat")
async def chat(
    request: ChatRequest,
    user_id: int = Depends(get_current_user_id)
):
    # 生成缓存key
    cache_key = f"{hash(request.message)}:{hash(str(request.context))}"
    
    # 检查数据库缓存
    cached_response = database_client.getLLMCache(cache_key)
    if cached_response:
        return Result.ok(cached_response)
    
    # 缓存未命中，调用LLM
    answer, contexts = await service.chat_with_references(request.message, None)
    
    # 构建响应
    reply = {
        "content": answer,
        "type": "text",
        "sources": [r.model_dump() for r in refs],
        "suggestions": []
    }
    
    result = {
        "conversation_id": conversation_id,
        "reply": reply,
        "related_questions": []
    }
    
    # 写入数据库缓存
    database_client.setLLMCache(cache_key, result)
    
    # 保存对话历史
    database_client.saveConversationMessage(conversation_id, request.message, answer)
    
    return Result.ok(result)
```
